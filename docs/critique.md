# Katakuri — Honest Self-Assessment

> **v0.1.0 snapshot (2026-10-17).** This is written at the moment the crate is
> release-ready but unpublished. Some of the "weak" items below are what a
> `0.2` would attack; none of them are hidden from the README or the book.

## What is strong

**Golden parity, not "it looks right."** The tokenizer is verified against 26
single-sequence and 3 batch golden vectors generated by the reference
implementation (HF Rust `tokenizers` 0.21.4) with the consumer's exact call
shape. The goldens and the vocab are committed, so CI replays parity with no
network. This is the strongest evidence in the crate and the model for how
every future parity claim should be made.

**Strict construction.** Every input format bigger than the implemented subset
rejects with a typed error instead of silently approximating: unsupported
normalizers, pre-tokenizers, post-processors, model kinds, truncation
strategies/directions, added-token flags, divergent special-token maps,
out-of-subset activations, impossible layer counts. Silent divergence is the
worst failure mode for a data plane, and the design treats it as such.

**Review density.** Twenty-two root findings across four review loops; twenty
fixed here with regressions, nine of them correctness- or security-critical
(P1s) — namespace shadowing, case-fold aliasing, token redaction, redirect
downgrade, final-sigma divergence, the empty-token infinite loop, sparse-id
capacity, and two 32-bit arithmetic traps. Several would have shipped
silently; all are now regression-held and published
(`book/src/design/review-record.md`).

**A boundary that survived contact with consumers.** The dependency ledger is
small and justified line by line, the default build has no network or async
runtime, and the `NoDevice` path is exercised rather than assumed. The crate
does one layer and does not drift into compute.

**Diagnostics-first validation.** `validate_weights` reports every divergence
in one error. That is a small thing that changes how a mis-shipped weight file
gets debugged.

## What is weak

**One architecture class.** `BertSpec` is BERT/MiniLM-shaped only. Anything
else needs a new spec type. This is the correct trade for the measured consumer
(Ijima), but it means "model specs" is narrower than the name suggests.

**No lock-free (or any) cache concurrency story.** `$KATAKURI_HUB_DIR` can be
shared by two processes and both may fetch; the atomic rename keeps readers
safe, but there is no locking. Fine for the single-process deployments
targeted today — untested otherwise.

**Windows is unverified.** The cache path encoding was designed for
case-insensitive filesystems, and `rename` is documented atomic there, but no
Windows CI job exists. Reserved device names (`con`, `nul`, `aux`) pass the
filename grammar. macOS/Windows claims rest on reasoning, not runs.

**Kani is unexecuted.** Three `#[cfg(kani)]` harnesses exist, covering span
arithmetic, overflow rejection, and offset containment. Kani is not installed
in CI (or on the authoring machine), so they have never been run here — the
proofs are currently a specification of intent, not a gate. `verify`'s SMT export is also deferred upstream (karpal-verify
0.6.1 operator mapping).

**Revision pinning is deferred.** The cache is keyed by the revision *string*.
`main` re-resolves; a consumer that wants immutability must pass a commit sha
by hand. There is no `x-repo-commit` check, so the cache cannot tell you the
branch moved.

**Breadth before depth in the hub.** No metadata API, no siblings listing, no
xet/LFS protocol, no resumable download. Plain `resolve` + redirects covers
the observed case and nothing more.

**Concurrency performance is unmeasured.** Parsing is single-threaded and
zero-copy, which is the right shape, but no benchmark claims exist. There is
no claim to defend, and none is made.

## What the review loops addressed

Twenty findings, all fixed and regression-held (full ledger in the book's
[Review Record](../book/src/design/review-record.md)):

| Slice | Findings | The ones that mattered most |
|---|---|---|
| S1 safetensors | 2 | zero-length spans falsely rejected as overlapping; doc links under `-D warnings` |
| S2 tokenizer | 8 | per-character lowercase (final sigma); empty added-token infinite loop; ignored boundary flags and truncation direction; divergent special-token mappings; checked id conversion |
| S3 model specs | 3 | capacity vs cardinality (sparse ids); wasm32 `+ 1` wrap; 32-bit tensor-count overflow |
| S4 hub | 7 | sidecar namespace shadowing; case-fold aliasing; bearer token in `Debug`; non-200 accepted as content; non-HTTPS URL; feature-unsafe docs; https→http redirect downgrade |

Seven recurring classes were distilled from those findings: Unicode case
folding is context-sensitive where the reference is not; zero-length matches
loop forever; cardinality is not capacity; 32-bit arithmetic is where
"obviously correct" checks fail; shared namespaces alias; ignored
configuration is silent divergence; and a scheme check on the first request is
not a check on the redirect chain.

## What would make this a confident `0.2`

In priority order, and none of it is contracted:

1. Execute the Kani harnesses in CI (the harnesses already exist).
2. A Windows CI job, and rejection of reserved device names.
3. Commit-sha pinning via the response header, closing the revision-keying
   gap honestly.
4. A second architecture spec, driven by a measured consumer — Minuet's
   surface was never measured.
5. Cache locking, if and when a multi-process deployment shares a root.

Until then: `0.1.0` is a small, sharply-bounded, well-reviewed loader — which
is exactly what it was built to be.
