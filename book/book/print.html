Katakuri

Introduction

Katakuri is the model-ecosystem layer over Zunesha: safetensors weight loading, BERT-class WordPiece tokenization, architecture specs as typed data, and hub access.

The one who sees ahead — the weights are ready before the compute begins.

What it does

Katakuri owns everything around tensor math:

  • safetensors — parse and fully validate a weight file into a zero-copy manifest, then hand tensor bytes either to host memory or to a zunesha::Buffer on a device.
  • tokenizer — a bespoke WordPiece engine that reproduces the reference tokenizer byte-for-byte on committed golden vectors.
  • model — a typed BERT config.json (BertSpec) plus weight-layout manifests validated against a parsed weight file.
  • hub — model-file fetch and a content-addressed, digest-verified local cache; offline-first, with the network transport behind its own feature.

The hard boundary: Katakuri never computes

No forward implementations. No autodiff. No kernels. No shader compilation.

Katakuri stops precisely where tensor math starts. It loads, validates, and describes the data consumers compute over. Consumers implement forward passes on their tensor engine of choice — exact CPU math today, Borsalino-class GPU compute later. The same weights feed either path; Katakuri takes no side.

This is the structural form of the workhorse / precision doctrine: Borsalino is the workhorse, Amari is the precision — and Katakuri is the data plane both read from, so neither has to own a model loader.

The boundary is enforced by the dependency ledger as much as by policy: no tensor framework, no BLAS, no GPU compute crate, and no async runtime appears anywhere in the tree.

Why it exists

On 2026-10-16 zip 8.6.0 was yanked from crates.io, making candle-core 0.11.0’s zip ^8.6.0 requirement permanently unsatisfiable. Amari’s CI lost 15 of 16 workflow jobs at dependency resolution — before a single line compiled — over a candle dependency that repo never used.

The strategic response was not a bespoke candle replacement. It was an IA-owned layer for the parts that are not tensor math, so the ecosystem does not inherit a heavy ML framework’s dependency risk for weight parsing, tokenization, config validation, and file fetching. That is Katakuri.

Layering over Zunesha

CrateRole
ZuneshaGPU device substrate — device, queues, memory, zunesha::Buffer
BorsalinoGPU compute abstraction — compiles shaders, dispatches
GoldenweekGraphics (render) layer over Zunesha
KatakuriThis crate. Model ecosystem: weights, tokenization, specs, hub. Never computes.

Weight data lands in zunesha::Buffer when a device exists, and in host memory via Zunesha’s NoDevice path otherwise — GPU-less hardware (Ijima’s deployment class) is a first-class requirement, not a fallback. Katakuri is a consumer of Zunesha, never a wrapper: buffers flow through, and alignment and lifecycle obligations remain Zunesha’s.

Status

0.2.0: slices S1 (safetensors), S2 (tokenizer), S3 (model specs), S4 (hub), and S5 (MLP specs + validated checkpoints) are complete. The first four replaced candle and hf-hub in Ijima’s embedding path — the tokenizer bit-for-bit identical to the reference on the committed golden vectors, the forward pass staying in the consumer, as designed. S5 adds the Amari learned-rewrite seams: the ia-mlp architecture family, the TensorManifest layout proposal for Borsalino’s tensor extension, and checkpoint loading under an explicit trust policy.

Getting Started

Add the dependency

[dependencies]
katakuri = "0.1"

The default feature set is std only. No tensor framework, no HTTP client, no crypto crate: parsing, tokenization, and spec validation build and run offline on GPU-less hardware. Network fetch is opt-in (hub-net) — see Feature Flags.

For a local checkout:

[dependencies]
katakuri = { path = "../Katakuri" }

First code: encode text

The tokenizer needs only a vocab. This is the real sentence-transformers/all-MiniLM-L6-v2 vocabulary, but any BERT-class line-per-token vocab.txt works — line i is token id i.

use katakuri::tokenizer::Tokenizer;

fn main() -> Result<(), Box<dyn std::error::Error>> {
    let vocab = std::fs::read("vocab.txt")?;
    let tokenizer = Tokenizer::from_bert_vocab_txt(&vocab)?;

    let encoding = tokenizer.encode("Katakuri never computes.", true);
    println!("ids:  {:?}", encoding.ids);
    println!("mask: {:?}", encoding.attention_mask);
    Ok(())
}

Against the MiniLM vocab this prints:

ids:  [101, 29354, 18569, 2072, 2196, 24134, 2015, 1012, 102]
mask: [1, 1, 1, 1, 1, 1, 1, 1, 1]

encode never pads and never fails: unknown pieces become [UNK] by design. Use encode_batch when you want BatchLongest right-padding (that is the only place padding is observable).

From a tokenizer.json instead of a bare vocab:

#![allow(unused)]
fn main() {
use katakuri::tokenizer::Tokenizer;

let json = std::fs::read("tokenizer.json")?;
let tokenizer = Tokenizer::from_tokenizer_json(&json)?;
}

Only the BERT-class subset is accepted (BertNormalizer, BertPreTokenizer, TemplateProcessing with [CLS] A [SEP], WordPiece, LongestFirst truncation). Anything else rejects with a typed error rather than silently diverging from a configuration Katakuri does not implement.

Next: read weights

The rest of this page shows fragments; they assume the surrounding function is fn main() -> Result<(), Box<dyn std::error::Error>>.

#![allow(unused)]
fn main() {
use katakuri::safetensors::SafeTensors;

let bytes = std::fs::read("model.safetensors")?;
let weights = SafeTensors::parse(&bytes)?;

println!("{} tensors", weights.tensor_count());
for name in weights.names() {
    let tensor = weights.tensor(name)?;
    println!("{name}: {:?} {:?}", tensor.dtype(), tensor.shape());
}
}

Parsing validates the whole manifest up front: dtype, shape, offsets, span arithmetic, and non-overlap. A file that parses is a file whose every tensor can be sliced safely.

Next: validate a model end to end

#![allow(unused)]
fn main() {
use katakuri::model::BertSpec;

let spec = BertSpec::from_config_json(&std::fs::read_to_string("config.json")?)?;
spec.validate_weights(&weights)?;          // names, dtypes, shapes, completeness
spec.check_tokenizer_compatibility(&tokenizer)?; // ids fit the embedding table
}

Runnable examples

The repository ships three, each runnable against a checkout:

cargo run --example inspect-safetensors -- tests/fixtures/tiny-model.safetensors
cargo run --example encode-text
cargo run --example fetch-and-validate --features hub-net   # first run downloads ~90 MB
cargo run --example fetch-and-validate --features hub-net -- --offline

fetch-and-validate fetches all-MiniLM-L6-v2 through the hub, parses the config into a BertSpec, validates the real 90 MB weight file against the derived layout, and cross-checks tokenizer/embedding capacity. --offline accepts cache hits only and never touches the network.

Concepts & Doctrine

Four ideas explain every design decision in this crate.

1. The never-computes boundary

Katakuri loads, validates, and describes. It never computes.

Katakuri doesKatakuri does not
Parse and validate a safetensors manifestForward passes
Hand tensor bytes to host memory or zunesha::BufferAutodiff, gradients, optimizers
Tokenize text into idsKernels, shaders, dispatch
Validate a config + weight layout against each otherNumeric weight inspection

The boundary is not modesty; it is the point. A model loader that also contains a compute graph drags in a tensor framework, and a tensor framework drags in a dependency tree nobody in the IA ecosystem audited — which is exactly the failure that created this repo. Consumers implement the forward pass on the engine they already trust:

Katakuri:  config.json → BertSpec
           model.safetensors → validated manifest
           tokenizer.json → Tokenizer
              ↓  (typed data: ids, shapes, names, dtypes, byte views)
Consumer:  forward pass on exact CPU math (Amari-style) or Borsalino GPU

Because upload_to_device produces a zunesha::Buffer while the host view stays valid, the same weights feed either path with no re-loading and no conversion step. Katakuri takes no side in the workhorse/precision split.

2. Strict construction: typed rejection over silent divergence

Wherever an input format is bigger than the subset Katakuri implements, the implemented subset is strict and everything outside it is a typed error — never a best-effort interpretation.

The rule matters most for parity surfaces. A tokenizer that silently approximates BertNormalizer produces embeddings that are almost right, which is worse than an error, because nothing downstream can tell. So:

InputOutside the subsetResult
tokenizer.json modelanything but WordPieceUnsupportedModel
normalizeranything but BertNormalizerUnsupportedNormalizer
pre-tokenizeranything but BertPreTokenizerUnsupportedPreTokenizer
post-processortemplates other than [CLS] A [SEP]UnsupportedPostProcessor
truncation strategyanything but LongestFirstUnsupportedTruncationStrategy
truncation directionanything but RightUnsupportedTruncationDirection
added-token flagssingle_word / lstrip / rstripInvalidTokenizerJson
config.json hidden_actanything but gelu / gelu_approximate / reluInvalidConfigJson
config.json model_typeanything but "bert"InvalidConfigJson

The same doctrine governs geometry. BertSpec rejects non-positive or u32-overflowing size fields, a hidden_size not divisible by num_attention_heads, a non-finite or non-positive layer_norm_eps, and an impractical num_hidden_layers > 1024 (the last one exists because 5 + 16L + 2 overflows a 32-bit usize and would panic on wasm32 — strict construction rejects it at parse time instead).

Validation is also diagnostics-first: validate_weights collects every divergence (missing, unexpected, wrong shape, wrong dtype) into one error rather than reporting the first. One round trip tells you everything wrong with a weight set.

3. Golden-parity methodology

Parity claims are cheap; parity evidence is not. The tokenizer is verified against the reference implementation, not against a reading of its source:

  1. Generate goldens with the reference. 26 single-sequence cases plus 3 batch cases were produced by the real HF Rust tokenizers crate (0.21.4 — the exact crate and version Ijima pinned), using Ijima’s exact call shape (BatchLongest padding, encode(text, add_special_tokens = true)).
  2. Commit the goldens and the vocab. tests/fixtures/golden_minilm.json and tests/fixtures/minilm-vocab.txt live in the repo, so CI replays parity with no network and no model download.
  3. Pin the corpus to the hard cases. Case folding, NFD accent stripping, punctuation isolation, subword segmentation, CJK per-character handling, emoji → [UNK], literal [SEP]/[CLS] in raw text, ## literals, empty/whitespace inputs, and an over-length input truncating to exactly 128 tokens ending in [SEP].
  4. Assert ids and masks byte-for-byte. The committed goldens are the contract; regenerating them is only legitimate when the corpus changes.

A useful side effect: the test builds a tokenizer from the plain vocab with typed defaults and asserts it matches the goldens. That proves vocab.txt + BERT defaults ≡ tokenizer.json semantics for this model, so both constructors are exercised against the same evidence.

4. Content-addressed cache, digest on read

The hub’s cache is trustworthy only as far as its digests. Every read re-hashes:

{root}/{owner}~{model}/{revision}/content/{filename}    ← bytes
{root}/{owner}~{model}/{revision}/digests/{filename}    ← lowercase-hex sha256 + "\n"
  • A path returned by Hub::get held bytes whose sha256 matched the sidecar at return time.
  • Every later Hub::cached hit re-reads the file, re-hashes it, and compares. A tampered or truncated entry reads as a miss, not as data; under CacheFirst it is refetched and atomically overwritten.
  • Writes are atomic: full write to a same-directory temp file, then rename. No reader ever sees a partial file, and a crashed write cannot leave a half-written entry that later verifies.

Three structural choices make the cache safe rather than merely correct:

  1. Namespace separation. Content, digest sidecars, and temporary files occupy separate directories, and a sidecar is named exactly the filename. A fetched file can therefore never be mistaken for a sidecar — even a file literally named x.sha256 lands under content/.
  2. Case-safe encoding. Every case-bearing component is encoded (uppercase X → ^ + lowercase x); ^ is outside the segment grammar, so encoded names contain no uppercase and cannot alias on a case-insensitive filesystem. Revision V1 and v1 are different cache entries on macOS and Windows too.
  3. Strict path grammar. Owner, model, revision, and filename are single segments of ASCII alphanumerics plus -._. .., /, NUL, and everything else reject at construction, so a hostile repo id cannot escape the cache root.

The cache is revision-keyed, not commit-keyed: the revision string is used exactly as given. main re-resolves and can name different bytes over time; pin a commit sha when you need immutability. The known limitations (no file locking, Windows reserved device names, revision-string keying) are recorded in The Hub — recorded, not hidden.

Feature Flags

Katakuri is additive-feature-gated. The default build is the offline core — weights, tokenization, specs — and every network or verification surface is opt-in.

default = ["std"].

The zero-dependency default (for the hub surface)

The base crate depends on five small crates — thiserror, serde_json, zunesha, and the two Unicode tables the reference tokenizer itself uses. The hub adds nothing to that: the Fetch trait is a dependency-free seam, so the cache, path validation, and digest machinery build and test with no network client at all. sha2 arrives only with digest (and hub, which depends on it — one hash implementation, re-exported rather than duplicated), and ureq only with hub-net. There is no async runtime anywhere.

sha2 is pinned to exactly 0.11.0: 0.11.1 raised its MSRV to Rust 1.88, above this crate’s declared 1.85.

What each gate buys

  • verify — three ObligationBundles (IsOffsetInBounds, IsSpanConsistent, IsManifestNonOverlapping) exported for the karpal SMT/Lean/Kani backends, tier Impossible: the validator makes the illegal state unrepresentable. See Verification.
  • digest — katakuri::digest: artifact_sha256 (and the S4-compatible sha256_hex alias). Local artifact identity for checkpoint metadata (ia.schema-hash, ia.model-hash) without pulling in the hub.
  • checkpoint (std + digest) — katakuri::checkpoint: load_validated, TrustPolicy, ValidatedCheckpoint. The ordered trust pipeline; see MLP Specs & Validated Checkpoints.
  • hub — katakuri::hub: RepoId, Revision, Hub, Policy, the Fetch trait, and the re-exported sha256_hex. Offline-first: with a warm cache, no network code path is reachable.
  • hub-net — UreqFetcher (blocking, rustls, HTTPS-only including the redirect chain, optional bearer token). The only surface in this crate that opens a socket.

The Hub: Fetch & Cache

katakuri::hub (feature hub) replaces hf-hub as the model-file acquisition path: a revision-keyed, digest-verified local cache with a pluggable transport seam. hub-net adds the blocking ureq/rustls transport.

Resolving a file

#![allow(unused)]
fn main() {
use katakuri::hub::{Hub, RepoId, Revision, UreqFetcher};
use std::sync::Arc;

let repo = RepoId::parse("sentence-transformers/all-MiniLM-L6-v2")?;
let rev = Revision::main();
let hub = Hub::with_default_root(Arc::new(UreqFetcher::new()))?;

let config_path = hub.get(&repo, &rev, "config.json")?;
let config = std::fs::read_to_string(config_path)?;
}

get resolves a digest-verified cache hit, or fetches, verifies, writes atomically, and returns the local path — never a URL. The URL used is the Hub resolve form (https://huggingface.co/{repo}/resolve/{rev}/{filename}).

Policies

#![allow(unused)]
fn main() {
use katakuri::hub::Policy;

// CacheFirst (default): verified hit short-circuits; miss or corrupt fetches.
let path = hub.get_with(&repo, &rev, "config.json", Policy::CacheFirst)?;

// AlwaysFetch: re-fetch even on a hit, verify, atomically overwrite.
let path = hub.get_with(&repo, &rev, "config.json", Policy::AlwaysFetch)?;
}

Offline lookups are a separate, infallible call:

#![allow(unused)]
fn main() {
if let Some(path) = hub.cached(&repo, &rev, "config.json") {
    // digest-verified hit — no network, no error path
}
}

cached returns None on a miss, a corrupt entry, or an unreadable one. It never fetches and never errors, which is what makes the offline-first story testable: warm the cache, then swap in a transport that panics if touched.

Cache root

$KATAKURI_HUB_DIR, else $HOME/.cache/katakuri/hub. Override per-process:

KATAKURI_HUB_DIR=/var/cache/katakuri cargo run --example fetch-and-validate --features hub-net

Layout — content, digests, and temp files never share a namespace:

{root}/{owner}~{model}/{revision}/content/{filename}
{root}/{owner}~{model}/{revision}/digests/{filename}

The sidecar holds the lowercase-hex sha256 plus a trailing newline and is named exactly the filename. A fetched file therefore cannot shadow a sidecar, whatever it is called.

Tokens

UreqFetcher::new() is unauthenticated (public repos; the Hub’s anonymous rate limit is roughly 3000 requests / 5 minutes). For gated repos or higher limits:

#![allow(unused)]
fn main() {
use katakuri::hub::UreqFetcher;

let fetcher = match std::env::var("HF_TOKEN") {
    Ok(token) if !token.is_empty() => UreqFetcher::with_token(token),
    _ => UreqFetcher::new(),
};
}

The token is sent as Authorization: Bearer … and is never rendered by Debug (UreqFetcher prints Some(<redacted>)).

Security notes

  • HTTPS only, end to end. The initial URL is checked, and the ureq agent is built with https_only(true), so an https → http redirect downgrade in the middle of the Hub’s 307 chain refuses to connect rather than leaking the bearer or accepting plaintext bytes. (This was review finding 20: the initial-scheme check alone did not cover redirects.)
  • Digest on read. A path is only returned after its bytes hashed to the sidecar digest, and every subsequent cached hit re-hashes. Tampering reads as a miss and triggers a refetch.
  • Strict path grammar. Owner, model, revision, and filename are single segments of ASCII alphanumerics plus -._; .., /, NUL and everything else reject with UnsafeRepoPath before any path is built. Path traversal is unrepresentable, not filtered.
  • Case-safe encoding. Uppercase becomes ^ + lowercase in every case-bearing component, so V1/v1 and Config.json/config.json cannot alias on a case-insensitive filesystem.
  • Body ceiling. 1 GiB (MAX_BODY_BYTES), read with one byte of headroom so an over-limit body is rejected rather than silently truncated.
  • Strict final status. Only HTTP 200 after redirects is accepted; a 204 or 304 is a failed fetch, never empty content to be cached.

Known limitations

Recorded, not hidden:

  • No file locking. Concurrent writers to the same cache entry are not serialized; the atomic rename keeps readers from seeing partial content, but two processes may both fetch. Fine for the single-process deployments this targets; revisit if a multi-process daemon shares a cache root.
  • Revision-string keying. The cache key includes the revision exactly as given. A branch or tag (main) re-resolves and can name different bytes over time. Pin a commit sha for reproducibility. S4 performs no header-based (e.g. x-repo-commit) pinning; that is deferred.
  • Windows reserved device names are open. The segment grammar admits con, nul, aux and friends; those become problematic only if such a character device is actually opened on Windows. Not yet rejected.
  • No metadata API. No model listing, siblings, or uploads — file fetch only. No xet/LFS protocol implementation: the plain resolve URL with redirect-following covers the observed behavior.

Replacing the transport

Fetch is the whole transport contract — one method, no dependencies:

#![allow(unused)]
fn main() {
use katakuri::KatakuriError;
use katakuri::hub::Fetch;

#[derive(Debug)]
struct Fake {
    body: Vec<u8>,
}

impl Fetch for Fake {
    fn fetch(&self, _url: &str) -> Result<Vec<u8>, KatakuriError> {
        Ok(self.body.clone())
    }
}
}

That is how the hub’s tests run hermetically, and how an embedder plugs in an existing HTTP client instead of ureq.

MLP Specs & Validated Checkpoints

Katakuri 0.2.0 adds a second architecture family — the ia-mlp feedforward spec — and the validated checkpoint loader Amari’s learned rewrite needs (Amari 0.25.0 Tasks 40–45, wishlist W1 + W2 + W5). They land together because they are coupled: the loader’s shape/schema check and its canonical parameter order both come from the spec.

MlpSpec — the ia-mlp family

BertSpec and MlpSpec are separate families sharing invariants, not one generalized config parser. A BERT-shaped model still rejects under MlpSpec, and an MLP rejects under BertSpec — each error names the families it knows ("bert" / "ia-mlp") so a caller can route.

{
  "model_type": "ia-mlp",
  "schema_version": 1,
  "input_width": 64,
  "hidden": [{"width": 256}],
  "head": {"width": 1},
  "hidden_activation": "gelu_erf"
}

Strict grammar, parsed by MlpSpec::from_json:

FieldRule
model_typerequired, exactly "ia-mlp"
schema_versionrequired, exactly 1 (forward-compat gate)
input_widthrequired, 1..=4096
hiddenrequired array, length 0..=8; each {"width": w}, 1..=16384
headrequired, {"width": 1} — the head produces a scalar score
hidden_activationrequired: relu, tanh, gelu_erf, gelu_tanh

Every bound is checked with plain comparisons — no +1, no subtraction, no multiplication at parse time — so the checks cannot wrap on a 32-bit target (the wasm32 lesson from S3, re-applied). The largest derived weight is 16384 × 16384 = 268_435_456 elements, which fits a 32-bit usize; cargo check --target wasm32-unknown-unknown keeps that true.

Unrecognized keys inside the spec are tolerated and ignored (the S3 discipline: the consumed surface is strict, training metadata is not ours). The checkpoint metadata namespace is where unknown keys reject — see below.

Canonical parameter order

expected_tensors() returns names and shapes depth-first, layer order:

hidden.0.weight  [w0, input]
hidden.0.bias    [w0]
hidden.1.weight  [w1, w0]
hidden.1.bias    [w1]
…
head.weight      [1, w_last]
head.bias        [1]

That order is the canonical ordering the checkpoint round-trip guarantee relies on — it is not an implementation detail.

Activations are named semantics, not code

Activation names the function; Katakuri never evaluates it:

  • Relu — max(0, x)
  • Tanh
  • GeluErf — exact 0.5x(1+erf(x/√2)); erf is the consumer’s
  • GeluTanh — candle’s GeluApproximate semantics (the exact function Ijima pinned), now a named choice instead of an inherited backend detail

load_validated — the trust policy

0.1.0’s SafeTensors::parse takes &[u8] and is value-blind. The checkpoint module is the scoped, named reversal: it opens a file, applies an explicit TrustPolicy, parses through S1 unchanged, and optionally scans values. parse itself stays value-blind.

Every policy field is an explicit choice — nothing is silently on:

#![allow(unused)]
fn main() {
use katakuri::checkpoint::{TrustPolicy, load_validated};

let policy = TrustPolicy {
    regular_file_only: true,   // symlinks/FIFOs/devices/dirs reject; hardlinks pass
    byte_cap: 64 << 20,        // checked before reading, read bounded by the same cap
    verify_schema_hash: true,  // ia.schema-hash vs the parsed spec's canonical JSON
    verify_model_hash: true,   // ia.model-hash vs the data section
    reject_nonfinite: true,    // NaN / ±Inf in F32 tensors reject
};

match load_validated(std::path::Path::new("model.safetensors"), &policy) {
    Ok(checkpoint) => {
        // spec, manifest, metadata, and tensors in canonical order
        let _ = checkpoint.spec.input_width;
    }
    Err(error) => eprintln!("checkpoint rejected: {error}"),
}
}

The pipeline is ordered and failure is total (no partial loads):

  1. regular-file check (symlink_metadata + O_NOFOLLOW on Unix + fstat on the opened descriptor; plain metadata elsewhere)
  2. byte cap
  3. read
  4. S1 parse (value-blind)
  5. metadata convention (ia.*)
  6. ia.spec → MlpSpec (strict)
  7. shape/schema agreement with expected_tensors() (diagnostics-first)
  8. schema/model hash verification — before the value scan, so a tampered file reports a hash mismatch rather than a value diagnostic
  9. optional nonfinite scan
  10. manifest assembly in canonical order

Hardlinks are regular files and are accepted. Subnormals are finite and are kept: they are legal f32 values, and whether the compute layer tolerates them is its question, not the loader’s. A failed load returns no partial result — ValidatedCheckpoint exists only when every enabled check passed.

The metadata convention (ia.*)

KeyMeaning
ia.specthe spec JSON itself (required)
ia.schema-hashsha256 of the parsed spec’s canonical JSON
ia.model-hashsha256 of the safetensors data section
ia.provenance.training-datafree-form replay/training-data binding, 1..=4096 bytes

Any other ia.* key rejects (UnknownIaMetadata): the namespace is strict, and forward compatibility is a schema_version bump, not a silent ignore. Metadata outside the ia. namespace is the writer’s business and is carried through untouched.

MlpSpec::canonical_json() is the deterministic, key-sorted serialization the schema hash covers, so semantically identical specs hash identically regardless of input whitespace or key order.

The layout manifest (T0 co-sign, unstable)

TensorManifest is the shared Katakuri ⇄ borsalino-tensor contract (Borsalino PR #61 §4.4): canonical order, F32 pinned, row-major contiguous, no padding, plus the determinism metadata the compute layer needs (no bit-pattern-changing fast paths — wishlist W3’s Katakuri side).

It is data, not buffers: no zunesha dependency, and binding entries to device buffers is the consumer’s concern. The type is not frozen in 0.2.0 — it freezes only after the Borsalino tensor-extension session reviews it against T0’s zero-copy needs. That gate is named in the module docs.

Feature gates

SurfaceRequires

A consumer that only describes architectures never links the hash or file-I/O surfaces (wishlist W6). The hub feature carries digest in its dependency list; a hand-rolled --cfg feature="hub" build without digest is a compile error, and the crate-root docs assert the graph in a doctest.

What this is not

Katakuri does not compute the forward pass. The MLP’s matmuls, the GELU, and the determinism question all live in the consuming engine — Amari’s hand-rolled tiny matmul in 0.25.0, Borsalino’s kernels later. This page describes weights, shapes, ordering, and trust decisions, and stops there.

Canonical form and physical layout

Two independent canonicalizations keep checkpoints stable:

  • MlpSpec::canonical_json() — a hand-rolled, fixed-key-order document (pinned byte-for-byte by a unit test). Its bytes are what ia.schema-hash digests. It deliberately does not iterate any serde_json map: a downstream consumer enabling serde_json’s preserve_order feature would otherwise change the digest through feature unification.
  • ValidatedCheckpoint::canonical_data_bytes() — tensor data concatenated in canonical parameter order (expected_tensors() order, depth-first by layer). Loading honors the file’s physical offsets and does not require canonical arrangement; the bit-stable guarantee is over this canonical concatenation, not the input bytes.

The trust-policy open uses libc’s per-ABI O_NOFOLLOW/O_NONBLOCK (unix-only, and optional — activated through the digest feature that compiles the checkpoint module, so default and no-default builds carry no checkpoint-only dependency) — hand-derived flag tables were wrong twice during S5’s development, which is exactly the failure mode a dependency on the verified source eliminates.

safetensors

Weight parse + validate: dtype, shape, layout, and manifest checks over the borrowed input bytes, plus a device-upload seam over zunesha::Device. No math.

Format

A safetensors file is an 8-byte little-endian u64 header length N, then N bytes of JSON header, then the data buffer. Header keys are tensor names (or __metadata__); each tensor entry is {"dtype", "shape", "data_offsets": [start, end]} with offsets relative to the start of the data region.

Parsing

#![allow(unused)]
fn main() {
use katakuri::safetensors::SafeTensors;

let bytes = std::fs::read("model.safetensors")?;
let st = SafeTensors::parse(&bytes)?;

println!("{} tensors, {} data bytes", st.tensor_count(), st.data_len());
for name in st.names() {
    let t = st.tensor(name)?;
    println!("{name}: {:?} {:?} ({} bytes)", t.dtype(), t.shape(), t.bytes().len());
}
}

The parse is zero-copy: SafeTensors borrows the slice and tensor views are &[u8] windows into it. Nothing here needs a device, which is why GPU-less hardware is the first-class path.

A minimal valid file (the doc-test in lib.rs) is eight bytes of header length 2 followed by {}:

#![allow(unused)]
fn main() {
let bytes: &[u8] = &[2, 0, 0, 0, 0, 0, 0, 0, b'{', b'}'];
let st = SafeTensors::parse(bytes)?;
assert_eq!(st.tensor_count(), 0);
}

Validation contract

All validation happens at parse time. Every tensor reachable afterwards satisfies:

RuleViolation
header length ≤ 100 MB (DoS guard, matches the reference)HeaderTooLarge
header length fits the fileHeaderLengthExceedsFile
header is a JSON objectHeaderParse / HeaderNotAnObject
__metadata__, when present, is a string→string mapInvalidMetadata
entries carry exactly dtype, shape, data_offsetsInvalidTensorInfo
dtype is a safetensors dtypeInvalidDtype
start ≤ end ≤ data_lenOffsetOutOfBounds
end − start == elements × dtype_size (checked u64)SizeMismatch / SizeOverflow
no two spans overlap (gaps allowed)OverlappingTensors

Gaps are legal because real files have them; overlaps never are, because they would make two named tensors aliases of the same bytes. Zero-length spans are filtered out of the overlap check — an empty tensor claims no bytes and cannot conflict (review finding 1).

Types

Dtype is the safetensors set: Bool, U8, I8, F8E5M2, F8E4M3, I16, U16, F16, Bf16, I32, U32, F32, F64, I64, U64, with byte_size() and parse() (canonical string, case-sensitive).

Tensor exposes dtype(), shape(), data_offsets(), bytes(), and elem_count(). SafeTensors exposes names(), tensor_count(), metadata(), data_len(), and tensor(name).

let st = SafeTensors::parse(&bytes)?;

match st.upload_to_device("embeddings.word_embeddings.weight", &device) {
    Ok(device_tensor) => {
        // device_tensor.buffer: zunesha::Buffer — GPU-resident weights.
        // device_tensor.meta:   the manifest entry the bytes were validated against.
    }

The host view remains valid after an upload, so the same weights can feed a precision CPU path or a Borsalino GPU path. Alignment and lifecycle obligations are Zunesha’s; Katakuri passes buffers through and never restates them.

tokenizer

A bespoke WordPiece (BERT-class) engine: a transcription of the reference pipeline, verified byte-for-byte against committed golden vectors.

Constructing

From a line-per-token vocabulary (BERT defaults: ## continuation, [UNK]/[CLS]/[SEP]/[PAD] resolved from the vocab, max_input_chars_per_word 100, no truncation):

#![allow(unused)]
fn main() {
use katakuri::tokenizer::Tokenizer;

let vocab = std::fs::read("vocab.txt")?;
let tokenizer = Tokenizer::from_bert_vocab_txt(&vocab)?;
}

From a tokenizer.json (strict BERT-class subset):

#![allow(unused)]
fn main() {
let json = std::fs::read("tokenizer.json")?;
let tokenizer = Tokenizer::from_tokenizer_json(&json)?;
}

The decoder and padding fields are accepted and ignored — single-sequence encode never pads and encode_batch always uses BatchLongest.

Encoding

#![allow(unused)]
fn main() {
let encoding = tokenizer.encode("Katakuri never computes.", true);
assert_eq!(
    encoding.ids,
    [101, 29354, 18569, 2072, 2196, 24134, 2015, 1012, 102]
);
assert_eq!(encoding.attention_mask, [1, 1, 1, 1, 1, 1, 1, 1, 1]);
}

Against the committed MiniLM vocab. encode is infallible: unknown pieces become [UNK], and truncation (when configured) keeps max_length − 2 content tokens before wrapping in [CLS] … [SEP].

Batching right-pads to the batch longest:

#![allow(unused)]
fn main() {
let batch = tokenizer.encode_batch(&["a dog", "the weights are ready"], true);
// [0] ids:  [101, 1037, 3899, 102, 0, 0]      mask: [1, 1, 1, 1, 0, 0]
// [1] ids:  [101, 1996, 15871, 2024, 3201, 102]
}

Encoding carries ids: Vec<u32> and attention_mask: Vec<u32>.

Introspection

#![allow(unused)]
fn main() {
println!("{} tokens", tokenizer.vocab_size());   // 30522 for MiniLM
println!("max id {}", tokenizer.max_token_id()); // 30521
}

max_token_id() is the max over the vocab table, added-token ids, and the four special ids. It is what the model spec checks against the embedding table — capacity, not cardinality: a sparse vocab with entry id 40000 in a 30522-entry table preserves the count but would index past the table (review finding 11).

Pipeline

encode runs, in order:

  1. added-token split on the raw input — leftmost match, longest first;
  2. BertNormalizer — clean_text, CJK spacing, accent strip (strip_accents.unwrap_or(lowercase)), then per-character lowercase;
  3. BertPreTokenizer — whitespace split (whitespace removed) plus punctuation isolation;
  4. WordPiece — greedy longest-match-first with ## continuations; failure or an over-length word emits a whole-word [UNK];
  5. truncation to max_length − 2 content tokens (LongestFirst, single-sequence), then [CLS] … [SEP];
  6. padding — only in encode_batch (BatchLongest).

Step 2 lowercases per character, not via str::to_lowercase. That is not a performance choice: Rust’s str::to_lowercase applies the contextual final sigma rule, so ΟΣ would become ος where the reference produces οσ. The golden corpus pins the per-character behavior (review finding 3):

ΟΔΟΣ → "οδοσ" → [101, 1169, 29722, 29730, 29733, 102]
       ("ο" + "##δ" + "##ο" + "##σ")

Parity evidence

The test suite asserts ids and masks against tests/fixtures/golden_minilm.json — 26 single-sequence cases and 3 batch cases generated from HF Rust tokenizers 0.21.4 with Ijima’s exact call shape. The vocab fixture is committed, so parity replays offline. See Concepts for the methodology.

model

Architecture specs as typed data: strict BERT config.json parsing (BertSpec) and weight-layout manifests validated against a parsed safetensors file.

Specs are data, never code — no forward implementations live here, and no numerics: weight values are never inspected, only layout (names, dtypes, shapes, set completeness).

Parsing a config

#![allow(unused)]
fn main() {
use katakuri::model::{BertSpec, HiddenAct};

let spec = BertSpec::from_config_json(&std::fs::read_to_string("config.json")?)?;

assert_eq!(spec.hidden_size(), 384);
assert_eq!(spec.num_hidden_layers(), 6);
assert_eq!(spec.num_attention_heads(), 12);
assert_eq!(spec.intermediate_size(), 1536);
assert_eq!(spec.vocab_size(), 30522);
assert_eq!(spec.max_position_embeddings(), 512);
assert_eq!(spec.hidden_act(), HiddenAct::Gelu);
}

Real all-MiniLM-L6-v2 values shown; the same code parses any BERT-class config in the supported subset.

What is enforced

  • model_type must be the string "bert" — required; absent rejects.
  • architectures, when present, must contain "BertModel".
  • position_embedding_type, when present, must be "absolute".
  • hidden_act must be Gelu, GeluApproximate, or Relu ("gelu", "gelu_approximate", "relu"). "gelu_new" and friends reject.
  • Every size field (hidden_size, num_attention_heads, num_hidden_layers, intermediate_size, vocab_size, type_vocab_size, max_position_embeddings) must be a positive integer that fits u32; num_hidden_layers is additionally bounded at 1024.
  • hidden_size must be divisible by num_attention_heads.
  • layer_norm_eps must be finite and > 0.0; pad_token_id must fit u32.

Tolerated-and-ignored (inference-irrelevant training metadata): _name_or_path, attention_probs_dropout_prob, gradient_checkpointing, hidden_dropout_prob, initializer_range, transformers_version, use_cache, and any other unknown keys. Documented, never read.

Validating weights against the spec

#![allow(unused)]
fn main() {
use katakuri::safetensors::SafeTensors;

let bytes = std::fs::read("model.safetensors")?;
let weights = SafeTensors::parse(&bytes)?;

spec.validate_weights(&weights)?;
}

validate_weights derives the full layout manifest from the spec’s numbers (expected_tensors()) and checks that every expected tensor is present with that exact shape and dtype F32; nothing unexpected is present, except embeddings.position_ids, the sole sanctioned non-parameter tensor, and then only as I64 [1, max_position_embeddings].

Diagnostics are collected, not first-error-only: one error lists every missing / unexpected / wrong-shape / wrong-dtype line.

For MiniLM the manifest is 103 parameters; a real file carries 104 tensors (the extra is the position-ids buffer).

Cross-checking the tokenizer

#![allow(unused)]
fn main() {
spec.check_tokenizer_compatibility(&tokenizer)?;
}

The rule is capacity, not cardinality: no id the tokenizer can emit may index past the embedding table —

max_token_id() + 1 ≤ vocab_size      (checked as: max_token_id() < vocab_size)

The >= form is deliberate. On a 32-bit target (wasm32) max_id as usize + 1 wraps at u32::MAX, which would admit an id needing 2^32 embedding rows; max_id >= vocab_size is target-independent and algebraically identical on 64-bit (review finding 12).

A tokenizer smaller than the table is legal — vocab-padded configs simply leave rows unused. Only overflow rejects.

The error surface

All malformed, missing, or out-of-subset values return KatakuriError::InvalidConfigJson with a detail naming the field and the problem; a weight-set divergence returns KatakuriError::WeightLayoutMismatch with the full list. Both are constructed via thiserror, so the Display text is the diagnostic.

MLP specs (0.2.0)

Beside BertSpec, the model module carries the ia-mlp feedforward family — MlpSpec, MlpLayerSpec, and Activation (named semantics; approximations are named, never inherited). Full grammar, bounds, and the canonical JSON form are covered in MLP Specs & Validated Checkpoints.

Fetch + cache

#![allow(unused)]
fn main() {
use katakuri::hub::{Hub, Policy, RepoId, Revision, UreqFetcher};
use std::sync::Arc;

let repo = RepoId::parse("sentence-transformers/all-MiniLM-L6-v2")?;
let rev = Revision::main();
let hub = Hub::with_default_root(Arc::new(UreqFetcher::new()))?;

// CacheFirst: verified hit → path; miss/corrupt → fetch → verify → atomic write.
let path = hub.get(&repo, &rev, "model.safetensors")?;

// Explicit policy: re-fetch and overwrite even on a hit.
let path = hub.get_with(&repo, &rev, "config.json", Policy::AlwaysFetch)?;

// Offline only: digest-verified hit → Some(path); miss/corrupt → None.
if let Some(path) = hub.cached(&repo, &rev, "config.json") {
    let config = std::fs::read_to_string(path)?;
}
}

get returns a local path, never a URL. cache_path is a pure join: useful for display, logging, and pre-flight checks.

Root resolution: $KATAKURI_HUB_DIR, else $HOME/.cache/katakuri/hub. A custom root is just Hub::new(path, fetch).

The transport seam

#![allow(unused)]
fn main() {
use katakuri::KatakuriError;
use katakuri::hub::Fetch;

#[derive(Debug)]
struct Fake {
    body: Vec<u8>,
}

impl Fetch for Fake {
    fn fetch(&self, _url: &str) -> Result<Vec<u8>, KatakuriError> {
        Ok(self.body.clone())
    }
}
}

Fetch: Send + Sync + Debug with one method:

#![allow(unused)]
fn main() {
fn fetch(&self, url: &str) -> Result<Vec<u8>, KatakuriError>
}

Implementations must be HTTPS and must follow redirects per HTTP semantics. Errors flow through KatakuriError::HubFetch. Tests run on fakes, so the hub is hermetic; embedding a different HTTP client is one impl block.

Verification

Katakuri carries the Borsalino verification pattern in two independent forms: obligation bundles — machine-readable invariant specifications, exported as SMT-LIB scripts (feature verify; no obligations are discharged by the crate itself — a solver must consume the exported scripts). The karpal-verify SMT exporter has an upstream operator-mapping defect (Karpal#176), pinned pending fix and Kani harnesses (bounded model checking of the validation arithmetic).

The classes, distilled

Seven distinct failure classes account for all twenty findings. They are worth naming because each is a recurring way strict data-plane code goes wrong:

  1. Unicode case folding is context-sensitive where the reference is not. Parity surfaces must transcribe the reference’s exact per-character behavior, not Rust’s idiomatic equivalent (finding 3).
  2. A matcher that can match zero-length input loops forever. Anyone scanning for literal tokens must reject empty needles at construction and guard the scan (finding 4).
  3. Cardinality is not capacity. “How many entries” and “how large an index can this emit” diverge exactly when ids are sparse — and sparse ids are legal input (finding 11).
  4. 32-bit arithmetic is where “obviously correct” checks fail. + 1 after a u32 at its maximum, and 16·L at a large L, are both fine on 64-bit and broken on wasm32 (findings 12, 13). Compile the target, don’t reason about it.
  5. Shared namespaces create aliasing. Content vs sidecar, uppercase vs lowercase — any two things a filesystem might fold together must be separated structurally, not by convention (findings 14, 15).
  6. Ignored configuration is silent divergence. Accepting a flag you do not honour (lstrip, Left) changes output without an error; reject instead (findings 5, 6, 7).
  7. A security check on the first request is not a check on the chain. Redirects are part of the transport; enforcing a scheme at the entry point and letting the client follow a downgrade is a leak (findings 17, 18, 20).

Why this is published

The review loops were not a formality: nine retained findings were P1s in security (namespace shadowing, token redaction, redirect downgrade) or correctness (final sigma, the empty-token loop, sparse ids, both wasm32 arithmetic traps). Publishing them makes the classes reusable across the ecosystem rather than relearning them one crate at a time — and it keeps an honest record of what 0.1.0 survived before it shipped.

The remaining weaknesses that review did not close are recorded in docs/critique.md.

Classes worth reusing:

  1. Hand-copied ABI constants are a twice-failed class. Two independent hand-derivations of one flag table were both wrong, each in a different way, and both passed every local gate (the targets that would catch them weren’t compiled). The dependency carrying the verified per-arch values is cheaper than the third attempt.
  2. Blocking syscalls are denial of service in a validator. A trust-policy loader must bound its own wait: any open that can park (FIFO read end) needs the nonblocking flag even when the expected failure is later in the pipeline.
  3. Canonical serialization must not iterate unordered containers — including ones that are “usually” ordered. Feature unification in a downstream crate can flip the backing map; a canonical form is a protocol, and protocols do not inherit defaults.
  4. State guarantees over the canonical form, not the input bytes. A loader that accepts arbitrary physical layout owes a named, tested canonicalization — “round-trip byte-identical” without that qualifier was an overstatement review correctly rejected.
  5. A new dependency must be feature-scoped to the code that needs it. Target gating excludes platforms; only feature gating excludes configurations of your own crate.
