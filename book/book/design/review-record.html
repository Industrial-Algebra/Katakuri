Katakuri

Review Record

Every slice (S1–S4) ran a review loop before landing, capped at twelve rounds, with findings posted inline on the PR. Twenty-two root findings across those four loops; twenty were fixed here with a regression (severity split: 9× P1, 10× P2, 1× P3, all as graded on the PR threads). This page is the record, because a review that only leaves “LGTM” behind leaves nothing to learn from.

Three notes on what is counted:

  • Two findings are excluded from the twenty (both real, both dispositioned on the PR, both documented in the S1 section): a P3 that strengthened a weak test assertion — a test defect, not shipped-code behavior — and a P2 deferred upstream (the karpal-verify SMT exporter).
  • Every retained entry below was reproduced by a regression test (or, in one case, by a behavioral repro that cannot be hermetic — noted inline).
  • Not every finding was in shipped behaviour: finding 8 was in the test harness. That counts — a golden reader that silently truncates can make a parity proof lie.

The classes, distilled

Seven distinct failure classes account for all twenty findings. They are worth naming because each is a recurring way strict data-plane code goes wrong:

  1. Unicode case folding is context-sensitive where the reference is not. Parity surfaces must transcribe the reference’s exact per-character behavior, not Rust’s idiomatic equivalent (finding 3).
  2. A matcher that can match zero-length input loops forever. Anyone scanning for literal tokens must reject empty needles at construction and guard the scan (finding 4).
  3. Cardinality is not capacity. “How many entries” and “how large an index can this emit” diverge exactly when ids are sparse — and sparse ids are legal input (finding 11).
  4. 32-bit arithmetic is where “obviously correct” checks fail. + 1 after a u32 at its maximum, and 16·L at a large L, are both fine on 64-bit and broken on wasm32 (findings 12, 13). Compile the target, don’t reason about it.
  5. Shared namespaces create aliasing. Content vs sidecar, uppercase vs lowercase — any two things a filesystem might fold together must be separated structurally, not by convention (findings 14, 15).
  6. Ignored configuration is silent divergence. Accepting a flag you do not honour (lstrip, Left) changes output without an error; reject instead (findings 5, 6, 7).
  7. A security check on the first request is not a check on the chain. Redirects are part of the transport; enforcing a scheme at the entry point and letting the client follow a downgrade is a leak (findings 17, 18, 20).

Why this is published

The review loops were not a formality: nine retained findings were P1s in security (namespace shadowing, token redaction, redirect downgrade) or correctness (final sigma, the empty-token loop, sparse ids, both wasm32 arithmetic traps). Publishing them makes the classes reusable across the ecosystem rather than relearning them one crate at a time — and it keeps an honest record of what 0.1.0 survived before it shipped.

The remaining weaknesses that review did not close are recorded in docs/critique.md.

Classes worth reusing:

  1. Hand-copied ABI constants are a twice-failed class. Two independent hand-derivations of one flag table were both wrong, each in a different way, and both passed every local gate (the targets that would catch them weren’t compiled). The dependency carrying the verified per-arch values is cheaper than the third attempt.
  2. Blocking syscalls are denial of service in a validator. A trust-policy loader must bound its own wait: any open that can park (FIFO read end) needs the nonblocking flag even when the expected failure is later in the pipeline.
  3. Canonical serialization must not iterate unordered containers — including ones that are “usually” ordered. Feature unification in a downstream crate can flip the backing map; a canonical form is a protocol, and protocols do not inherit defaults.
  4. State guarantees over the canonical form, not the input bytes. A loader that accepts arbitrary physical layout owes a named, tested canonicalization — “round-trip byte-identical” without that qualifier was an overstatement review correctly rejected.
  5. A new dependency must be feature-scoped to the code that needs it. Target gating excludes platforms; only feature gating excludes configurations of your own crate.
